02 · documentation

Technical log

2.1

Partial observability: a maze neither agent fully knows

The environment is designed so that no agent receives the exact position of the whole map; each one only has the information its own sensor gives it. This decision turns the problem into a POMDP (partially observable Markov decision process): each agent's policy acts on an estimate of the environment, not on its true state.

The environment module keeps the exact position of both agents at all times, since it acts as the referee for determining encounters. That information, however, is never exposed directly to the decision policy.

2.2

The sensor: eight rays and a map of its own per agent

Each agent casts eight rays in fixed directions (North, Northeast, East, etc., clockwise). Each ray advances cell by cell up to a maximum range, and stops when it hits a wall, the edge of the board, or the other agent's position.

normalized distance per ray

$$d_{\text{ray}} = \frac{\text{free cells to the obstacle}}{\text{maximum range}} \in [0, 1]$$

Every cell a ray passes through gets marked as "known" in that agent's own internal map, not a shared one. Episode after episode, each agent builds its own partial representation of the maze, similar to the incremental mapping done by a robot equipped with lidar.

design simplification

A physical lidar only measures the time a beam takes to bounce back: it gives a distance, without saying what it hit. This implementation returns two separate channels per ray (wall_dist and agent_detected), meaning it already hands over the resolved classification instead of a raw reading. This was done to separate the reinforcement learning problem from the separate problem of perception and object classification.

2.3

Network architecture: twenty-six inputs, five outputs

Each agent's observation is turned into a 26-value vector: 2 correspond to its own normalized position, and 24 to the lidar readings. The latter come from each of the 8 rays contributing three components, not two: the normalized distance to the nearest wall, a binary flag for whether that ray detected the other agent, and the normalized distance to that agent if it was detected. So, 8 rays × 3 values = 24, plus the 2 for its own position, add up to 26. A single-hidden-layer network turns that vector into a Q-value for each of the five available actions.

forward pass

$$z_1 = xW_1 + b_1 \qquad a_1 = \text{ReLU}(z_1) \qquad Q = a_1 W_2 + b_2$$

The nonlinearity introduced by ReLU between the two layers is necessary: without it, the composition of linear transformations would be equivalent to a single linear transformation, regardless of the number of layers.

2.4

Exploration versus exploitation

At the start of training, the network's weights are random and its Q-values carry no real meaning. For that reason, the action isn't always chosen deterministically: with probability ε a random action is selected, and that probability decreases progressively as the network accumulates reliable evidence.

epsilon-greedy policy

$$a = \begin{cases} \text{random action} & \text{with probability } \varepsilon \\ \arg\max_a Q(s,a) & \text{with probability } 1-\varepsilon \end{cases}$$

2.5

Experience memory

Training only on the most recent transition would expose the network to sequences of strongly correlated experiences. The replay buffer stores a history of past transitions and trains on random samples drawn from that history, reducing that correlation and stabilizing learning.

where the training data comes from

There is no external dataset. Every episode is a simulation generated on the fly, played by the agents themselves (self-play). Each step produces a transition (observation, action, reward, next observation, done), which gets added to the buffer; training minibatches are sampled from there, not from a pre-existing dataset.

2.6

The Bellman equation

The core learning criterion states that the value of an action equals the immediate reward plus the best value achievable from the next state.

Bellman target

$$\text{target} = \begin{cases} r & \text{if the episode ended} \\ r + \gamma \max_{a'} Q(s', a') & \text{if it continues} \end{cases}$$

The distinction between the two cases matters: if the episode ended, there is no next state to draw additional value from, so no future term should be added.

2.7

Numerical instability: the network as its own target

The first version of training used the same network for both the prediction and the computation of the Bellman target. The result was numerical divergence (RuntimeWarning: overflow) up to a total loss of meaning in the produced values.

finding

The cause is indirect: with every network update, the target itself shifts, since it's computed using that same network. This creates a moving target that drifts in the direction of the latest error, producing a feedback loop that amplifies the error instead of reducing it.

The standard DQN fix is the target network: a copy of the parameters that only gets updated every so many episodes. The network being trained converges toward a stable target during that interval, instead of chasing a target that changes at every step.

if episode % target_update_every == 0:
    copy_weights(q_network, target_network)  # new frozen copy

After this fix, along with a moderate reduction in the learning rate, the predator's capture rate went from 4% at episode 50 to stable values near 100% by episode 600: the first consistent evidence that the agent was learning something real.

2.8

Deterministic loop: the insufficient cost of a collision

While training both agents simultaneously, a different problem showed up: in one evaluation episode, neither agent moved at all for 101 consecutive steps.

finding

Under a purely deterministic policy (no exploration), if the highest-Q action is invalid at the current position, the agent stays put. And since the state doesn't change, the network evaluates the same input again and picks the same action again: a loop with no way out.

The underlying cause was in the reward function: colliding with a wall cost the same as moving successfully, so the network had no signal specifically penalizing that behavior.

A specific collision penalty was added, tested at two different magnitudes:

Collision penaltyObserved behavior
−0.2The prey converged to staying permanently still: the risk of collision outweighed the marginal benefit of surviving one more step.
−0.05Varied, sustained movement; the deterministic loop disappeared without inducing excessive passivity.

2.9

Unspecified emergent behavior

With the penalty adjustment described above, a behavior pattern emerged that wasn't part of the original design: the prey stays still as long as it doesn't detect the predator, and only starts moving once its sensor picks up that signal.

step 23: predator detects prey = False | prey action = 4 (stay)
step 24: predator detects prey = True
step 25: prey action = 0 (up)  ← starts evading once detected

interpretation

It's a reasonable policy, if suboptimal: moving without need carries collision risk with no benefit if there's no threat nearby. The network arrived at this idea on its own, with no one programming it in: a wait-and-react strategy is cheaper than moving around aimlessly.

observed limit

This reactive policy depends entirely on the predator staying within sensor range. In a later evaluation run, the predator lost sight of the prey after a chase and stopped at (7,9), while the prey stayed at (9,0) (9 cells away) for the last 20 steps of the episode. Neither agent learned to actively search when it loses sight of the other; both just stay still in the absence of a signal, instead of exploring.

2.10

Non-stationarity in simultaneous training

When only the predator was learning, facing a prey with a random policy, its capture rate rose and settled at 100%. When training both agents simultaneously, the capture rate initially rises and then oscillates, without converging to a single value.

interpretation

This is the non-stationarity inherent to multi-agent environments: from either agent's perspective, the environment keeps changing, because the other agent is also updating its policy. Every improvement on one side forces the other to adapt, with no guarantee that a stable equilibrium exists between the two.

2.11

Open threads

These extensions are still pending:

  • Add a term to the prey's reward proportional to its distance from the predator, instead of basing it only on survival, to incentivize active evasion.
  • Extend the number of training episodes (or the network's capacity) to see whether the oscillation in 2.10 converges to an equilibrium or is a persistent cycle.
  • Log the squared error curve of train_step during training, to see the target network's effect directly instead of inferring it only from the capture rate.
